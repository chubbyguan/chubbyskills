# 十位创作者试用计划

状态：**待招募、待执行**。下表是空白记录模板，不是已有用户、访谈或留存数据。

验证问题：使用 Agent 的内容创作者，能否把自己的素材保存下来，并在之后用带来源的资料完成选题？第一轮不以 Star、安装次数或测试通过次数代替这个结果。

## 试用任务

招募 10 位有日常收藏和选题需求、愿意使用本地 Markdown 的创作者。记录他们常用的平台和 Agent，不预设反馈一定正面。

请每人按[创作者工作流](./creator-workflow.md)处理 3 条自己的真实素材，生成一份可引用的选题资料。先让用户独立操作；提供帮助时，记录卡点、具体帮助和耗时。7 天后经对方同意回访一次，了解是否再次使用以及原因。

不要求参与者提交 Cookie、API key、个人知识库或未经授权的素材。维护者只保留参与者同意记录的匿名结果和必要的脱敏错误信息。公开仓库只放匿名汇总，联系方式和原始访谈保留在参与者同意的私有位置。

## 统一口径

| 指标 | 怎么记录 |
|---|---|
| 开始人数 | 真正开始安装/运行的参与者；受邀但未开始单独记录 |
| 首次真实采集成功 | 保存了可阅读的真实正文、来源可回查；fixture、dry-run、登录页不计入 |
| 自动与人工分别统计 | 一条链接自动获取成功记“自动”；粘贴正文、导入保存文件等记“人工 fallback”；不把两者合成自动成功率 |
| 首次成功耗时 | 从开始安装/运行到第一条真实笔记核对通过的分钟数；同时注明是否由维护者协助 |
| 选题使用 | 用户确认至少一个选题有用，主要观点的原文引用可打开；仅生成文件不算 |
| 七日复用 | 首次试用后 7 天内再次采集或引用素材完成任务；仅对已满 7 天且取得反馈者统计 |
| 维护成本 | 每位用户的问题数、维护者协助分钟数、需要修改代码还是解释文档 |

报告成功率时同时给分子和分母，并说明自动、人工、未开始、未回访人数。没有回访结果记“未知”，不足 7 天记“未到期”，不要写成复用或流失。耗时优先报中位数并保留原始样本数。

## 试用后的决策

- 多人卡在安装：优先修安装路径，再增加能力。
- 采集需要大量人工处理：优先修最常用的平台和错误提示。
- 入库成功却找不到材料：检查索引、查询方式和来源质量。
- 能生成选题却无人复用：回看目标人群和实际写作流程，不把原因全部归给宣传。
