# 怎么选择内容采集与知识库工具

Chubby Skills 面向使用 Agent 和本地 Markdown 的内容创作者：把收藏的素材采集入库，再检索原文，整理成可引用的选题资料。是否适合你，取决于这条流程能否处理你的真实内容。

## 按任务选择

| 你要完成的任务 | Chubby Skills 的入口 | 选择时需要验证 |
|---|---|---|
| 保存一条视频、文章或图文素材 | 平台 skill / `tools/chubby_ingest.py` | 目标链接能否读取；是否需要登录态、字幕或本地音视频依赖 |
| 把多条素材整理到自己的库里 | Markdown 输出、`tools/chubby.py` 队列与重试 | 原文、来源、图片是否完整；失败是否可见 |
| 从已保存素材中找证据 | `tools/vault_index.py` 的关键词和语义检索 | 查询能否找回原文；默认 semantic-lite 的结果是否足够 |
| 用 Agent 形成带引用的选题 | 本地文件或知识库 MCP | Agent 是否读取原文、给出可打开的来源，而非只生成摘要 |
| 持续订阅更新 | 可与 RSS 工具配合 | 是否需要定时订阅、新内容发现，而不只是处理已有链接 |

完整操作见[创作者工作流](./creator-workflow.md)。[平台状态](./platform-status.md)列出适配范围和失败条件；定义检查通过不等于对应网站当前可抓取。

## 与其他工具怎么配合

以下是选择入口，不是性能排名。资料核对日期：**2026-09-16**。外部能力来自项目或厂商自述，本仓库没有完成同环境实测；以链接中的当前文档和你自己的样本为准。

| 工具 | 可以进一步了解什么 | 与本项目一起评估的重点 |
|---|---|---|
| [feedgrab](https://github.com/iBigQiang/feedgrab) | 多平台抓取、Markdown 输出、视频/播客转录 skill、MCP | 当前 README 已包含转录和 MCP，不能按“不支持转录”评价；比较常用平台的成功率、输出质量和后续入库成本 |
| [RSSHub](https://github.com/DIYgod/RSSHub) | 为不同网站生成 RSS 订阅源 | 适合从订阅发现内容；具体路由返回哪些字段、是否带正文，应按路由验证 |
| [Readwise Reader](https://readwise.io/read) | 阅读、标注与内容管理 | 检查目标内容支持情况、导出方式、费用，以及是否符合自己的阅读习惯 |
| [ima](https://ima.qq.com/) / [NotebookLM](https://notebooklm.google.com/) | 托管知识整理与问答 | 分别核对资料类型、数据处理方式、导出与引用能力，不把不同产品合并为一个能力结论 |

Agent Skills 定义的是技能的组织方式。采用同一格式有助于集成，但不能替代在具体 Agent 客户端中的安装和运行验证。

## 本地与云端的边界

| 能力 | 内容处理位置 | 费用与依赖 |
|---|---|---|
| 保存 Markdown、SQLite 索引、关键词与 semantic-lite 检索 | 本地 | 这些步骤不需要模型 API；采集仍需访问内容平台 |
| 本地音视频转录 | 本地 | 需要对应模型、`ffmpeg` 和计算资源；下载模型或媒体需要联网 |
| `content-enrich`、翻译等 DeepSeek 增强 | 配置的 API 服务 | 需 API key，内容会发给该服务，可能计费 |
| OpenAI embedding provider | 配置的 API 服务 | 笔记文本和查询会发给该服务，可能计费 |
| local embedding provider | 本地模型 | 需额外安装模型依赖并下载模型 |
| Agent 根据素材生成选题 | 取决于选择的 Agent 和模型 | 使用云端模型时，被读取的素材会进入该模型的上下文 |

默认本地存储不代表所有可选能力都离线，也不代表 Agent 客户端不向模型发送内容。

## 用自己的素材做选择

选 3 条日常会收藏的素材，分别记录采集是否成功、需要多少人工处理、能否找回原文、最后是否用于一次选题。把失败和手动导入一起记录，比平台数量或功能勾叉更能说明工具是否适合你。

维护者的统一记录方式见[十人试用计划](./user-pilot.md)。目前该计划只是记录模板，没有用户样本或留存结论。
