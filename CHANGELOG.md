# Changelog

## Unreleased

- `x-ingest --thread` collects an author's self-reply chain into a single note. It reads the author's public syndication timeline (`showReplies=true`) and follows only the direct `in_reply_to_status_id` chain belonging to the same author, so other people's replies and the author's separate branches stay out; each tweet becomes its own section, reusing the existing image and video handling, and the frontmatter records `note_type: thread` with `thread_count`, `thread_ids` and aggregated engagement. The SKILL.md limitations are explicit that this timeline is an unofficial endpoint whose results may be stale or incomplete, and that finding no follow-up replies is reported rather than passed off as a complete thread. Contributed by [@ritujain8638-source](https://github.com/ritujain8638-source) in [#37](https://github.com/chubbyguan/chubbyskills/pull/37); the maintainer follow-up on the same branch fixed a conversation guard that a shadowed variable had turned into dead code, removed two unused imports that failed the lint gate, and added 15 tests across timeline parsing, chain collection and rendering. **The live path is not verified**: on 2026-10-05 the "
syndication timeline returned `HTTP 429` on a single request, so the feature is covered by offline "
tests only — the SKILL.md limitations now say so, and a 429 prints an actionable next step instead "
of a bare error. Omitting `--thread` never touches that endpoint.

- Platform capture now works from a non-editable install, which was the remaining half of [issue #16](https://github.com/chubbyguan/chubbyskills/issues/16). The 14 skill directories ship in the wheel through a `package-dir` mapping (`bilibili-transcribe` → `bilibili_transcribe`): their distributed names are not legal Python package names, and renaming them would break the directory-shaped bundles `install_skill.py` hands to agents. The mapping needs no `__init__.py` inside a skill directory, so the portable bundle stays byte-identical to the repository copy. `skill_dir()` resolves both layouts, so a checkout and an install take the same code path; `chubby ingest …` was verified end to end against a real X post from a fresh `pip install .`. The CI job now asserts the entrypoint resolves instead of asserting the refusal, which is the behaviour it was written to pin.

- Added `doctor --credentials`. Losing a login session surfaces as a generic capture failure, and obtaining the credential in the first place is the most common friction in this class of tool. The report lists every credential the project reads, what each one unlocks, the exact steps to obtain the missing ones, and the **last real outcome** of each skill that depends on them, read from the run journal. Two deliberate choices: credential values are never printed (this output gets pasted into issues), and there is no liveness probe — a probe is a real authenticated request, i.e. exactly the traffic that triggers the risk controls the report exists to help with. Whether a session still works is answered by the last recorded run.

- README quickstarts (zh/en) now lead with the workflow the traffic actually arrives for. The first path is a real capture — `ingest` a public X post with the standard library alone, no yt-dlp, ffmpeg or model — and it shows the note's provenance frontmatter (source, author, timestamp, engagement counts) so the value is visible in one command. It is labelled as **one sample**, not a success rate, with the platform-variance caveat and a pointer to the fallback routes. The local-file import stays as the second path, described as the one that never touches the network and works in any environment.

- Non-editable installs are usable. `pip install .` (or `pipx install`) used to report `0.0.0` and, worse, write `chubby.yaml`, `inbox/`, `runs/` and `.chubby/` **into site-packages** — a read-only install could not run `init` at all. The cause was `ROOT` serving two roles at once: package data and the base for relative config paths. Relative paths now resolve against the config file's own directory (`resolve_path` bases on `CONFIG_BASE`, set by `load_config`), which keeps the documented "relative to this repository" promise for a checkout and writes next to the user's config once installed. Subprocesses inherit the invoking directory instead of `ROOT`, so a relative `--source` resolves where the user typed it. `read_version()` falls back to distribution metadata when no `VERSION` file sits next to the package, and `platforms/` plus `templates/` ship in the wheel so `doctor`, `subscribe`, `digest` and `site build` work installed.
- `ingest` now refuses a partial install where the message can say what to do: without the skill directories it reports that platform capture needs a full checkout (`git clone …`) rather than failing deep inside a subprocess with a missing-file error. The same guard covers the optional `content-enrich` step.
- CI gained an `installed-cli` job that installs the package non-editable, runs the knowledge-base flow from a directory outside the checkout, asserts nothing was written into site-packages, and checks that `ingest` fails with the checkout hint. Both regressions above shipped unnoticed because no job ever exercised this layout.

- README quickstarts (zh/en) now show the real transcript of the first run instead of describing it: `init` → `import` → `search` → `brief` from a fresh clone, with the actual output of each step. The virtualenv and `pip install -e .` step moved out of the critical path and is labelled optional — the core workflow needs only the standard library, so the first note now takes one clone and four commands.
- Added [docs/verification-model.md](docs/verification-model.md): the rule this project actually runs on, written down as a reusable pattern — three tiers of claim (declared capability / offline-reproducible / live-accepted) that must never be mixed, the 7-day acceptance protocol, the hard content boundary for generated public output and why a test must enforce it (it caught the unescaped `llms.txt` titles), and how third-party evidence is handled without promoting a status the project has not verified itself.
- Community round: [PR #34](https://github.com/chubbyguan/chubbyskills/pull/34) (nightcityblade, X Article preview golden) and [PR #35](https://github.com/chubbyguan/chubbyskills/pull/35) (zswwwww, yt-dlp captured failure exit codes) merged after review on the merge result; [PR #6](https://github.com/chubbyguan/chubbyskills/pull/6) closed with a local reproduction of its integration chain that confirmed the claim and corrected two details. Recorded in [docs/community-triage.md](docs/community-triage.md).

- Cluster heat now decays with age. Each distinct source still counts once, but it is weighted by how fresh that source's latest report is: full weight inside 24 hours, half from 24 to 48 hours, and nothing past 48 hours. The model is adapted from AIHOT's event-based trending — without it a five-source story from last week outranks a three-source story from this morning, which the 7-day site view made obvious. Ranking and display use the same decayed value, so an event is never shown below a colder one; when every report has aged out, the brief prints `N 条 / M 源` without a misleading `热度 0`. The raw distinct-source count is still published as `source_count`.
- `subscribe site build` now emits two agent-facing exits beside the HTML: `feed.xml` (RSS 2.0, one item per clustered event, linking to the original source) and `llms.txt` (llmstxt.org shape: event index, source health, content boundary). Both obey the same hard boundary as the pages — titles, sources, times, original links and heat only — and the leak test now scans them too. Text nodes in Markdown and XML escape only `&`, `<` and `>`, so `Euler's Formula` survives instead of becoming `Euler&#x27;s Formula`, while HTML attributes keep full escaping. `atom:link rel="self"` is emitted only when `--base-url` is absolute, rather than advertising a relative URL no reader can resolve.

- Repository hygiene: the personal vault instance that `init --vault` creates at the README's `creator-vault/` path is now git-ignored, as is the root `outputs/` working directory — a plain `git add .` can no longer publish private notes, generated digests, site output or locally built release tarballs. The output rule is root-anchored (`/outputs/`) so the tracked `examples/outputs/` samples keep working, and both rules only cover paths that were never tracked. `uv.lock` is now tracked as well: the development environment is built with uv (`uv lock --check` passes against `pyproject.toml`), so the resolved toolchain is reproducible instead of reappearing as an untracked file on every `uv run`.

- DashScope cloud backend live-verified (2026-10-04): 2-minute Chinese podcast via qwen3-asr-flash returned in 4s with the best transcript quality of the three verified backends (correct punctuation, ITN and proper nouns). Both cloud backends are now acceptance-verified.

- Fixed Groq cloud transcription being rejected before any upload: Groq's Cloudflare front blocks Python's default urllib User-Agent (403 on GET, connection reset mid-upload on POST). `CloudProvider.request` now always sends a desktop browser User-Agent and `Accept: application/json`. Verified live (2026-10-04): a 5-minute Chinese podcast returned in 3 seconds with 154 timestamped segments, and the second run replayed from cache with zero API calls.

- Added `subscribe site build`: a zero-JS, zero-template-engine static daily-report site (Python `string.Template`, templates in `templates/site/`) generated from the subscription SQLite queue, reusing the digest title-similarity clustering. Pages: index (7-day event stream sorted by heat+time), per-day archives (30 days), a source health table (7-day checks and success rate from `source_checks`), and an about page; `--site-name` and `--base-url` are injected into every internal link and the output directory defaults to `<vault>/30_Output/site/` (a generated artifact that may be overwritten). Public-site content is hard-bounded to titles, source names, publish times, original links, cluster heat and source health — never bodies, local vault paths, related-note titles or credentials; leak assertions (no absolute paths, no `00_Inbox`, no local username) are enforced by tests.
- Added `subscribe digest`: a daily intelligence brief over recent subscription entries. Zero-LLM by default — title/time/source/link from the subscription SQLite queue, non-LLM title-similarity event clustering (Jaccard over normalized keyword tokens, configurable threshold, heat = reporting source count), and vault related-note links per event; processed entries link to their local notes, unprocessed ones keep original URLs. Output goes to `<vault>/30_Output/` with metadata frontmatter and never overwrites an existing file. `--enrich` adds an optional DeepSeek layer (prescreen → score → Chinese summary, `DEEPSEEK_API_KEY`, prompts externalized in `templates/digest-prompts/` so standards change without code); model-generated content is always labeled 🤖 and fails loudly with a zero-LLM hint when the key is missing.
- Fixed `x-ingest` logged-in full-text fetch for X long-form Articles, which had gone dark after X's frontend rollout: the hardcoded `TweetResultByRestId` queryIds all returned 404. The script now discovers the current queryId at runtime from the `main.*.js` bundle referenced by x.com's homepage (regex over `queryId:"...",operationName:"TweetResultByRestId"`), caches it at `~/.cache/x-ingest/tweet-result-query-ids.json` with a 24h TTL, and falls back stale-cache → built-in list, preserving the warn-and-keep-preview degradation. The GraphQL request also sends the new feature set plus `fieldToggles` (`withArticlePlainText` / `withArticleRichContentState`) — without them the API returns title + preview only — and fetches by tweet id (the syndication article rest_id no longer works). Verified live against a real X Article: 2859-character body instead of the 100-byte preview.

## 0.14.0 - 2026-10-03

- Podcast local transcription now uses SenseVoice-Small through the shared `chubby_common/funasr.py` wrapper, the same stack as the video skills; faster-whisper (and its `av` pin) has been removed. SenseVoice returns plain full text, so podcast transcripts no longer carry per-segment timestamps.
- The experimental Atlas Cloud / MuAPI podcast cloud backends have been replaced by Alibaba Cloud Model Studio's DashScope `qwen3-asr-flash` (`--provider dashscope`, `DASHSCOPE_API_KEY`, OpenAI-compatible `chat/completions` with inline base64 audio). The synchronous response is normalized into the existing resumable state machine; audio over 7 MiB raw (10 MB encoded / 5-minute service limit) is rejected before submission with a pointer to local SenseVoice. Attribution for the original cloud-transcription requests (PR #3 / PR #5) is retained.
- `setup.sh podcast`, `check_env`/`doctor`, `platforms/podcast.yaml`, packaging extras and docs were updated to the funasr + DashScope stack.
- Local podcast transcription now offers Qwen3-ASR-0.6B as an opt-in model (`--provider local --model qwen3-asr-0.6b`) via a new `local_qwen_asr.py` backend (official `qwen-asr` package, transformers CPU float32, `max_new_tokens=4096` to avoid truncation). SenseVoice-Small remains the default; local model names are whitelist-validated. The optional `qwen-asr` dependency is not part of the default install. Measured comparison (M3 Pro CPU, 2026-10): SenseVoice RTF 0.11 vs Qwen RTF 0.80; Qwen is steadier on proper nouns but can hallucinate and lacks ITN.
- Groq long-audio support: files at or above the 25 MB free-tier limit are no longer rejected but automatically chunked with ffmpeg into 20-minute 16 kHz mono 64 kbps MP3 segments (~9.6 MB each). Chunks are submitted in order with per-chunk persisted progress (digests + durations in the existing state file, backward compatible with single-file states), so an interrupted run resumes without resubmitting completed chunks; text is concatenated in order and segment timestamps are shifted by cumulative chunk durations. HTTP 429 responses wait on Retry-After / exponential backoff within the overall `--cloud-timeout`.
- Added a second synchronous cloud provider `groq` (Groq `whisper-large-v3-turbo` via the OpenAI-compatible `audio/transcriptions` multipart endpoint, `GROQ_API_KEY`). `verbose_json` segment timestamps are kept as a Markdown appendix; files at or above the 25 MB free-tier limit are rejected before upload with a pointer to local SenseVoice.
